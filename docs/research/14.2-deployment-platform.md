# §14.2 Deployment platform — research report

**Research date:** 26 July 2026 (live web verification; AWS/Azure figures cross-checked against the vendors' machine-readable price APIs). Prices USD list, pay-as-you-go, ex-GST; AUD ≈ 1.5× indicative.

## Headline findings (things that changed vs. common knowledge)

1. **AWS App Runner is dead for new adoption.** It *is* in ap-southeast-2, but AWS closed it to new customers on 30 April 2026; security-maintenance mode only. The designated successor is **Amazon ECS Express Mode** (GA Nov 2025, all regions, no extra charge): one API call provisions a Fargate service + ALB + HTTPS + autoscaling; up to 25 Express services share one ALB. ([availability change](https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html), [Express Mode](https://aws.amazon.com/about-aws/whats-new/2025/11/announcing-amazon-ecs-express-mode/))
2. **Only AWS keeps Claude in-cloud AND in-Australia.** Bedrock's `au.*` geographic inference profiles (31 Oct 2025) route the entire request lifecycle only between Sydney and Melbourne — Claude Sonnet 4.5 (`au.anthropic.claude-sonnet-4-5-20250929-v1:0`) and Haiku 4.5; third-party reports (verify in console) add Opus 4.6 from ~April 2026. Beware: `apac.*` routes across all of APAC and `global.*` can route to the US. **Vertex AI has no AU region for Claude** (nearest residency Singapore). **Azure AI Foundry Claude went GA ~2 July 2026** but Global/US Data Zone only; AU "coming 2026". **Anthropic direct API**: workspace data stored in the US — not AU data-at-rest. ([AWS blog](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-bedrock-cross-region-inference-for-claude-sonnet-4-5-and-haiku-4-5-in-japan-and-australia/), [Vertex Claude](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude), [Foundry Claude](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/claude-models), [claude.com/regional-compliance](https://claude.com/regional-compliance))
3. **Cloud Run's managed custom-domain mapping is still Preview and NOT available in australia-southeast1/2** — an AU deployment needs a global external ALB (+~$18–20/mo) or a Firebase Hosting proxy. ([domain mapping](https://docs.cloud.google.com/run/docs/mapping-custom-domains))
4. **Of Fly/Render/Railway, only Fly.io has an AU region** — and Fly's new Managed Postgres has **no documented PITR**. Render and Railway have no AU region at all — fail residency outright.

## Option 1 — Google Cloud Run + Cloud SQL + GCS + Scheduler + Secret Manager

- **Regions**: Cloud Run in Sydney + Melbourne (Tier 2 pricing).
- **App cost (Sydney, 1 min-instance)**: instance-based 1 vCPU/512MiB always-on ≈ **$60/mo**; request-based with warm min-instance (CPU throttled while idle) ≈ **$14/mo + active time**.
- **Cloud SQL Postgres (Enterprise zonal)**: db-f1-micro $10.37/mo, db-g1-small $34.53/mo, 1 vCPU dedicated ≈ $66.6/mo. **PITR enabled by default on new Enterprise instances**, works on shared-core — but shared-core tiers are **SLA-excluded, labelled test/dev-only**; the conservative prod choice (~$70/mo w/ storage) makes Cloud SQL the dominant cost.
- **GCS**: $0.023/GiB/mo; versioning + **Bucket Lock / Object Retention Lock (WORM, regulator-grade)**.
- **Deploys**: revision-based zero-downtime, traffic splitting, instant rollback; first-class GitHub Actions + keyless WIF.
- **Previews**: best of any option — per-PR revision tags or services, idle ~$0.
- **LLM**: Vertex Claude **not in-region** — Singapore at best. Fails the in-region LLM goal.
- **Monthly**: prod ~$72–115 (incl. unavoidable $18 ALB for AU custom domain); staging $0–13.

## Option 2 — AWS: ECS Express Mode / Fargate + RDS + S3 + EventBridge Scheduler + Secrets Manager

- **App Runner**: closed to new customers — do not build on it. Use ECS Express Mode or plain Fargate+ALB.
- **App cost (Sydney)**: Fargate 0.25 vCPU/0.5–1GB always-on ≈ **$11–13/mo** (ARM ~20% less). ALB floor ≈ **$19–24/mo**, amortised across prod/staging/previews via Express Mode's shared ALB. **Trap to design out: NAT gateway ~$43/mo** — use public subnets with public IPs or VPC endpoints.
- **RDS Postgres**: db.t4g.micro single-AZ $18.25/mo + 20GB gp3 ≈ **$21/mo with PITR included**, standard SLA — matches 99.5%. Multi-AZ ≈ $43/mo (unnecessary). Managed minor-version patching. Aurora Serverless v2 floor $73/mo — not the budget option.
- **S3**: $0.025/GB/mo; versioning + **Object Lock** free.
- **Scheduler/Secrets**: EventBridge Scheduler effectively free; Secrets Manager $0.40/secret/mo.
- **LLM**: **Bedrock `au.*` Claude keeps inference within Sydney+Melbourne** — the only fully in-cloud, in-region option.
- **Deploys/previews**: rolling ECS deploys zero-downtime; GitHub Actions via OIDC + `aws-actions/amazon-ecs-deploy-express-service`. No first-class PR previews — ~1–2 days of workflow glue; each preview costs cents (shared ALB).
- **Monthly**: prod ≈ **$55–61**; staging ≈ $5–25 (Fargate desiredCount=0 idle; RDS stop limited to 7 days → needs a re-stop Scheduler loop).

## Option 3 — Fly.io / Render / Railway

| | Fly.io | Render | Railway |
|---|---|---|---|
| AU region | **Yes — `syd`, incl. Managed Postgres** | **No** | **No** |
| Managed PG + PITR | MPG young: backups/HA yes, **PITR not documented**, patching "not there yet" | Mature; PITR 7 days on Pro | Unmanaged container; no PITR/HA |
| Compliance | SOC 2 II; no ISO 27001 | SOC 2 II + ISO 27001 | SOC 2 II |
| Cost (prod+staging) | ~$55–60 | ~$65–85 | ~$25–50 |

**Verdict**: Render/Railway fail AU residency. Fly.io is credible and cheap but **no documented PITR** violates the hard requirement (self-managed WAL archiving would breach OPS-2); object storage via third-party Tigris; SOC 2-only posture thin for a "security paramount" client. Not recommendable today; re-check MPG in 6–12 months.

## Option 4 — Azure (reference only)

Container Apps GA in Australia East; PG Flexible B1ms ≈ $23/mo with PITR; Blob WORM. Total ≈ $78–85/mo. Claude on Foundry GA but **no AU residency yet**. Strictly dominated: pricier than AWS at this scale, no in-region Claude, no platform familiarity. Entra federation works identically against any platform — doesn't pull hosting toward Azure.

## Recommendation (ranked)

### 1. AWS — ECS Express Mode (Fargate) + RDS Postgres + S3 (Object Lock) + EventBridge Scheduler + Secrets Manager + Bedrock `au.*` Claude
The only platform satisfying **every** hard requirement *and* keeping the LLM call in-cloud and in-Australia — decisive for a system sending crew evidence documents to the model. Also the cheapest hyperscaler configuration (~$60–85/mo), with an SLA-backed managed DB at $21/mo (vs GCP where the equivalently cheap tier is SLA-excluded), and the developer's AWS fluency is a solo-operability asset during incidents. Cons, bounded: more infra surface than Cloud Run (VPC, ALB, IAM), previews need workflow glue, Express Mode is young (Nov 2025) — mitigated by plain ECS/Fargate underneath (zero-rewrite escape hatch). Avoid App Runner (sunset) and NAT gateways (cost trap).

### 2. GCP — Cloud Run + Cloud SQL + GCS
Best pure DX and solo-ops story (simplest deploys, near-free previews, revision rollbacks); compliant on data-at-rest residency. Loses on: (a) Vertex Claude can't run in Australia — LLM traffic to Singapore at best, needs client sign-off; (b) AU custom-domain gap forces an external ALB; (c) SLA-backed Cloud SQL makes it the pricier option. Choose only if the client accepts offshore LLM inference and values previews highly.

### Manual-touchpoint audit (OPS-2)

| Touchpoint | AWS (#1) | GCP (#2) |
|---|---|---|
| TLS issue/rotation | ACM auto-renew — zero touch | Google-managed certs — zero touch |
| OS/DB minor patching | RDS auto minor upgrades — zero touch | Cloud SQL managed — zero touch |
| DB major upgrades | Manual, planned, ~yearly (managed blue-green) | Same |
| Backups/PITR | Automatic; quarterly restore-test is human everywhere (partially scriptable) | Same |
| Staging DB cost control | Scheduler loop to re-stop RDS every 7 days | $0 as second database on prod instance |
| Preview lifecycle | Workflow glue you own | Near zero |
| Residual | IaC drift, dependency updates, secret rotation — identical everywhere | Same |

Net: neither finalist requires self-managed servers, DBs, TLS, or backup execution; recurring human tasks are backup-restore verification and yearly DB major upgrades.
